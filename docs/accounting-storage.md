# 复式账本的浏览器存储

每个账本使用独立的 IndexedDB 数据库，名称为 `cent-accounting-book/v6/<编码后的账本 ID>`，IndexedDB 版本从 1 开始，配置中的结构版本为 6。账本 ID 使用 `encodeURIComponent` 编码。早期开发阶段的复式数据库（含 v5）保留原样，不会自动读取或迁移；当前不提供旧版数据迁移。

沿用原版四个存储区：

| 存储区 | 内容 |
| --- | --- |
| `__items` | 每个根交易一条记录，完整子交易递归存于 `children`；主键为 `id`，索引为 `time`、`creatorId` |
| `__meta` | `{ id: "metaKey", value: ... }`；账户定义 `accounts`、标签 `tags`、用户标签组 `personal`、地图配置 `map`、币种设置 `currencySettings`、统计视图 `statisticsViews` 和账本时区 `timeZone` |
| `__config` | 同样使用 `metaKey` 包装；保存复式格式标识及账本名称、版本和时间 |
| `__stashes` | 原版 `update`、`delete`、`meta` 形状的增量记录，使用 `timestamp` 索引 |

`__items` 保留原版字段 `id`、`type`、`comment`、`creatorId`、`time`、`tagIds`、`images`、`location`、`__create_at`、`__update_at`，去掉 `categoryId`、交易级 `amount` 和 `currency`，增加 `entries` 和可选 `children`。关联子交易通过 `parentTransactionId` 指向父交易，完整内容递归保存于父交易的 `children`，不再独立写入另一条 `__items` 记录。

```json
{
  "id": "transaction-id",
  "type": "expense",
  "comment": "购买日用品",
  "creatorId": "me",
  "time": 1791294245710,
  "tagIds": [],
  "entries": [
    { "accountId": "费用账户UUID", "amount": 200000 },
    { "accountId": "资产账户UUID", "amount": -200000 }
  ],
  "__create_at": 1791294245710,
  "__update_at": 1791294245710
}
```

金额只保存在分录中，仍以 10000 为单位。每个账户只有一种货币，通过 `entry.accountId` 查询 `__meta.accounts` 确定币种。外币消费使用两条分录：原币资产与同币种费用账户；`entry.currency = { base, target, amount }` 保存原币实际金额，外部 `entry.amount` 仅保存 base 币种的估算。余额和借贷平衡读取 `currency.amount`，不读取估算；没有 currency 的普通分录读取 amount。交易级不保存金额、币种或汇率副本。换汇仍按每种账户原币分别验证借贷合计为零。

领域、IndexedDB 与导出统一使用 `type` 表达交易目的，不另存 `kind` 或 `purpose`。账户的 `type` 表达五类会计账户，`subtype` 表达账户用途；账户余额和成本由分录计算，不由交易名称决定。领域的备注、时间仍使用 `description`、`createdAt`、`updatedAt`。内存中的 `Transaction.currency` 是由账户还原的辅助值，不持久化或导出；换汇时取付款账户币种。`accounting-record.ts` 负责与原版存储字段的双向转换。图片保存为 `images` 中的数据 URL，文件名和图片 ID 保存在 `extra.imageMetadata` 中，读回时还原领域图片对象。

保存时只增改删除发生变化的交易，账户等元数据有变化才写入 `__meta`。交易记录、元数据、待同步增量和账本版本在同一个 IndexedDB 事务中提交，失败全部回滚。同一目标的待同步增量压缩为最后一次操作；保存时检查版本，拒绝覆盖其他页面刚完成的修改。GitHub 已接入复式增量同步，其他远端适配器尚未接入。

每个账户独立保存 `icon`（内置图标 class 或自定义 SVG），位于 `__meta.accounts`，随账户一起导入和导出。新建账户按账户类型提供默认图标，原分类预置账户沿用原来的图标；子账户拥有自己的图标，不继承父账户的修改。尚未设置图标的账户在展示时使用默认图标。

账户定义使用独立 UUID，presetKey 仅用于预置名称的双语显示及模板选择。持久化分录只包含 `accountId`、`amount` 和可选 `currency` 原币金额，不含独立 id。复式编辑行拥有临时 UUID，保存时移除。父账户只通过 parentId 组织账户，汇总时计算自身及全部后代的分录，不能再把子账户金额记到父账户。

## 新账本默认模板

`default-account-catalog.ts` 保存精简模板的名称、图标、层级和翻译标识；`createDefaultAccountingData` 仅在创建新账本时生成独立 UUID。模板共有 33 个账户：现金、微信、银行卡、支付宝；独立负债账户信用卡和花呗，不设置“待还款”账户或父级；餐饮下的早餐、中餐、晚餐、零食、饮料；交通下的地铁、公交、出租；少量购物、居住、医疗、其他费用及工资／其他收入。

微信默认 1,000 元，用一笔 `opening_balance` 交易借记微信、贷记“期初权益／微信期初权益”，不计收入／费用。余额可通过编辑该交易改成实际值。其他账户余额为零。

地铁交通卡为独立 `prepaid` 资产，专属币种 UUID 与账户 UUID 不同，币种元数据关联账户，成本币种为 CNY，自动启用多币种。不创建虚构充值或期初交易，也不假定已经有汇率；实际充值／消费后按现有成本规则计算。默认仅提供一个 `fixed_asset` 子类型的“贵重物品”资产账户，不创建电脑／手机子账户、累计折旧账户或账户级折旧规则。每笔物品购买使用该账户，在购买交易中独立设置区间折旧子交易；不生成示例购买或每日持久化折旧。

账户管理沿用五类说明，在模板账本中提供可展开的新手指南，介绍支付、充值、还款、父子汇总与折旧。默认收起说明，让账户列表优先可见。模板名称和专属币种显示支持中英文，用户改名后保留自定义名称。已有账本不自动补入模板。预置名称、图标和层级直接由当前账户模板定义。

账户列表用缩进、连接线和展开箭头表示父子关系，每行显示账户子类型、父账户名称（或独立账户）及可见的直接子账户数量。父账户的汇总余额标注“含子账户”，包括隐藏的已归档子账户；换汇平衡分组不混合累加不同币种的余额。子类型名称支持中英文，自定义子类型保留原值，不更改账户数据。

## 统计读取与默认视图

统计页面复用原来的日期切片、ECharts 趋势图、日历以及账户占比图／列表。默认进入本月的日常收支／支出视图；另有资产分析、固定资产折旧两个预置视图。资产分析默认选择净资产，再切换资产／负债。所有视图按账本主货币展示，不增加分类存储或统计金额副本。

顶部沿用原版“＋”与菜单入口，自定义筛选器与三个预置视图并排显示，可横向滚动。新增时复用账户、备注、标签等筛选表单，并输入名称保存；筛选内可选择分析种类（日常收支、资产分析、固定资产折旧）、分析指标和资产分析角度（余额趋势、期间变动），无需预先切换顶部视图。账户选项和可用条件跟随种类、指标更新；切换种类清除原条件，切换指标清除不适用的账户范围与资产用途，取消不改变页面。确认和命名保存均提交分析配置与筛选条件，编辑已有筛选器也可更换分析种类；菜单可编辑、删除和使用原排序界面调整顺序。已保存视图的临时修改以星号提示，点击保存图标覆盖当前条件。`statisticsViews` 按账本保存在 `__meta`，随账本 JSON 导出／导入及元数据增量日志保存，不写入交易条目。每个视图保存分析类型、指标、资产分析角度、完整筛选条件与日期模式；周／月／年采用相对当前期间的偏移，自定义日期保存绝对边界。默认视图继续提供未筛选的起点。

`statistics.ts` 将完整交易历史转换为只读统计分录。统计账户筛选费用／收入分录，关联账户筛选涉及该账户或其子账户的交易；两者可以结合标签、创建者及交易类型。外币费用镜像依据 `presetKey` 的原账户关联归组，不能按名称合并。父账户自身分录及每个子账户组互不重叠，归档账户继续参与历史统计。图表、汇总和明细使用同一批命中分录；明细按交易 ID 合并后可以打开原交易，派生折旧只能查看其购入交易。

筛选复用原来的弹窗容器、账户级联选择、标签包含／排除、创建者勾选和金额范围组件，确认后生效，取消保留原条件。日常收支中的 `accountIds`、`relatedAccountIds` 是级联选择器展开后的精确 ID 集合；取消一个子账户后，已勾选的父账户不会自动将它重新纳入。未设置集合表示不限，空账户／创建者集合表示未选择任何项。`accountId` 继续用于图表下钻及资产余额、折旧物品的单项选择，包含其后代。包含标签采用任一匹配，排除标签优先。筛选弹窗的备注输入复用原版表单组件，只匹配交易备注，忽略大小写和首尾空格，可与账户、标签、金额等条件组合。搜索页继续复用原搜索输入框及清空、回车／按钮提交交互，关键词匹配备注、账户名称和交易类型。金额范围以主货币的单条收支分录绝对值判断，退款符号保持不变。日期继续使用原来的周／月／年／自定义控件。

收支分析只归集收入和费用账户，排除转账、充值、换汇本金，仍统计费用账户的手续费，继续提供趋势、日历和占比图；退款等负值使用列表。资产分析使用资产和负债账户，默认指标显示“所有者权益（净资产）”，等于资产减负债。权益账户记录期初资本、投入和换汇配平，不单独提供分析图，也不重复累加到净资产。余额视图使用截至所选日期的完整历史，包含期初及所选期间之前的交易；账户筛选在完整成本重放后应用。资产、负债及净资产构成使用可表达正负方向的水平条形图，可切换账户列表；净资产构成的负债显示为负数，点击条目仍可下钻。

收支及折旧使用保存的购买区间子交易，自动折旧按自然日分摊，整数累计差额保证总额守恒。累计额、账面价值和每日费用使用同一截止口径，不再切换月末计提与每日估算；未来部分不计入已发生费用。缺少换算依据时显示待换算。

资产分析提供余额趋势与期间变动两个角度。期初余额由开始日期之前的历史计算，仅是期间报告数字，无需新增期初余额交易。`getStatisticsBalanceActivity` 复用账户估值规则，一次重放外币成本，逐笔计算所选账户范围的主货币余额变化，再归集期间增加／减少。期初加增加减减少严格等于期末，按整笔交易合并后才分正负，因此组内转账、购入固定资产的资产互转会抵消；借款同时增加资产与负债，不增加净资产。选择一个账户后可以查看其转入／转出。变动趋势按天／月汇总；变动结构为各账户期末减期初，条形图保留增加与减少的符号。汇总增加／减少按钮、账户金额和明细入口可打开交易；父账户本身与子账户分开计数，保存的购买区间折旧子交易可以查看购入交易。所有统计保持只读。

资产与折旧分析复用收支的关联账户、备注、金额范围、交易类型、用户和标签包含／排除组件。资产条目条件作用于期间变动：先重放完整历史，计算每笔主货币变化，再筛选条目；汇总、变动结构、趋势和明细共用命中结果。启用条目条件时展示“净资产／资产／负债变动（筛选）”，不把筛选交易的合计冒充真实余额；余额趋势暂不可选。`getStatisticsBalanceActivity` 保留真实期初／期末作为计算上下文，只有未筛选时用它们展示期初加增加减减少等于期末；筛选视图只展示命中的增加、减少和净变动。`accountChanges` 保存互不重复的独立账户贡献，组内转账的净值为零，但筛选后仍可查看这笔交易及各账户的增减。区间交易在每个趋势桶内重新投影，分桶合计保持与整个期间一致，查询不写入交易。

`getStatisticsFilteredBalanceActivities` 先按当前选中的指标应用金额条件，确定交易 ID 集合，再用该集合计算净资产、资产和负债三个指标，保持净资产变动等于资产变动减负债变动。账户明细沿用同一集合，不在下钻后重新以单账户金额筛选。资产用途筛选限制资产部分，负债仍作为净资产的抵减项；正常未使用条目条件的余额查询不改变口径。

折旧筛选优先使用子交易自己的备注、标签和用户，未填写时沿用购入交易的元数据；关联账户可命中购入的支付账户，类型可选择购入或折旧。金额范围使用主货币的每日折旧值。用命中的折旧条目确定购买 ID 集合，期间费用、累计折旧、剩余价值及趋势均限定为同一批物品；共用资产账户时不按账户 ID 混合物品，累计和剩余值仍按完整历史计算。筛选未命中时三个指标都为零。

资产分析在“总资产”角度提供 `assetUsage` 筛选：普通账户、充值卡、固定资产，切换净资产／负债时清除用途条件。用途按账户子类型判断，固定资产账户的余额直接扣除截至查询时刻已经发生的区间折旧。账户范围与用途条件取交集，余额及变动仍重放完整历史，不能先过滤交易。未使用条目条件时，净资产／负债卡片保留各自完整口径。

固定资产折旧提供 `depreciationStatus` 筛选：使用中、已折旧完。以购买及区间子交易为依据，在所选期间末日判断；尚未购入的物品不命中。费用、期末值、趋势与明细使用同一组命中的购买交易，不在趋势各点重新筛选状态。日期沿用原控件：余额和累计额截至结束日期，期间费用仅取查询交集。筛选只改变只读报告。

## 主货币估值规则

换汇平衡账户统一归在一个权益父账户下，父账户使用独立 UUID 和 `presetKey: system:currency-trading`。人民币、外币及各储值卡的独立币种分别创建子账户，通过 `parentId` 关联；它们仍各自持有单一币种。`currency_trading` 仅保留为领域识别平衡分录的通用标记，不为每个币种增加子类型，编辑页不显示该系统标记，改为展示父账户。父账户不能参与分录或作为期初余额对方账户，也不直接汇总不同币种的原币金额，账户管理展示各子账户的独立余额。普通父子账户仍要求同币种，跨币种层级仅用于这个系统分组。

新换汇或充值在创建币种子账户时自动创建或复用父账户。加载现有同结构账本时，store 将已有平衡账户整理到父账户下，保留原账户 ID、币种和交易引用；下次保存账本时一起写入元数据，不修改历史分录。

交易列表右侧及详情顶部展示本笔交易的净资产（所有者权益）变化：资产变化减负债变化。分录采用借方正、贷方负，因此只累加资产与负债分录，不重复累加收入、费用或权益分录，也不展开父账户或关联子交易。增加显示绿色正数，减少显示红色负数，零变化保持中性；账户转账、还款、借款和等价购入资产通常为零，折旧与手续费减少净资产，退款增加净资产。详情展示每个账户的实际增减，不再显示单独的“交易金额”。

这项展示从原币分录派生。换汇按实际扣款、到账和手续费分录倒推成交比例，把资产分录统一到付款币种，手续费形成净变化；不使用当前行情计算换汇交易的盈亏。展示换算是临时计算，缺少报价时明确显示原币，不按 1:1 混合币种。

`__meta.value.currencySettings` 保存账本主货币 `baseCurrency`、启用状态 `multiCurrency`、自定义货币和快捷币种。创建或修改资产账户为其他币种时，应用 store 在同一次账本写入中自动启用多币种；显式导入外币资产账本也自动启用。账户表单的币种选择不再依赖事先打开开关，历史数据中的外币资产也会被识别。原“汇率与货币”页面显示启用状态，继续管理主货币与快捷入口，不提供手动开关、报价编辑或联网刷新。旧 `rates` 与自定义货币 `rateToBase` 仅为文件格式保留，不作为新版本估值依据。更换主货币无需已有汇率，不修改历史分录。

`deriveExchangeRates` 从账户剩余成本与原币余额提取双向平均比例，外币和自定义储值币种使用同一套核算。`exchangeValueRate` 优先直接比例，无直接比例时使用中转币种最少的路径；没有连接路径时返回缺失，不查询外部行情、不读取旧行情缓存或假设 1:1。设置页报价方向沿用原页面：1 主货币 = rate 目标货币。编辑、补录、删除交易后重放历史并重新推导。总资产逐个计算账户剩余成本；父账户不重复汇总，有余额但缺少成本或换算依据时显示缺失提示。

换汇以一条 `type: "currency_exchange"` 记录保存。条目不保存 `exchange`，`deriveCurrencyExchange` 根据分录和 `subtype: "currency_trading"` 权益账户推导付款、到账及可选手续费账户；不依赖分录顺序，遇到缺失或重复的角色拒绝读取。正向换汇平衡分录对应付款币种，负向对应到账币种。`Transaction.exchange` 仅为内存中的派生结果。实际扣款 `withdrawn`、实际到账 `received` 和手续费 `fee` 均从对应分录读取，成交汇率通过 `getCurrencyExchangeRate` 计算为 `received / (withdrawn - fee)`，不保存副本。该比例是 1 付款币种兑换的到账币种单位数。实际扣款已包含手续费；没有明确手续费时以最终收付计算有效汇率，不猜测银行价差。

系统为每个币种生成独立UUID的权益账户，`subtype: "currency_trading"`。例如扣款7010 CNY，到账1000 USD，手续费10 CNY，分录为：付款资产−7010 CNY、人民币换汇平衡+7000 CNY、手续费费用+10 CNY、美元换汇平衡−1000 USD、到账资产+1000 USD。无手续费时四条分录；有手续费时五条分录。账户与交易原子提交，换汇账户自动复用；普通复式分录不能手动使用换汇平衡账户。

新导出统一使用 `schemaVersion: 17`，支持原币分录、独立货币和完整购买子交易。仅接受当前格式，旧开发备份和未知字段整份拒绝；不读取账户折旧规则、辅助面值、旧 purpose 或重复金额／汇率。旧 Cent JSON / ZIP 不支持导入。

## 外币与自定义储值币种统一核算

账户页面选择“充值卡”自动创建该账户专属币种，币种 UUID 与账户 UUID 分开，`customCurrencies.accountId` 指向卡账户。其他资产账户不能复用其币种，费用和换汇平衡账户可以使用同币种分录。自动开启多币种，隐藏币种选择和期初余额，充值从实际交易建立成本。外币普通账户仍直接选择币种。账户 `currency` 表示唯一的余额单位，其他币种的资产账户默认以当前主货币作为 `costCurrency`。成本币种不是第二个余额；使用后不能重新指定。统一使用原“支出／收入／复式”编辑器，账户页不提供专用充值或消费按钮。消费原币余额在分录 `currency.amount`，充值/换汇原币余额在分录 `amount`；不保存辅助面值或平均汇率。旧辅助面值格式不支持导入或迁移。

转入通过“复式 → 换汇／充值”录入，按到账账户子类型自动识别：充值卡保存 `type: "topup"`，备注仍由用户填写。例如实付 100、到账 110 独立储值单位，分录为：现金 −100、成本币种平衡 +100、目标币种平衡 −110、资产账户 +110。独立储值币种即使 1:1 充值也保存完整的四条分录；普通同币种资产转入保存 `transfer`，包含转出与转入两条资产分录，按普通转账计算，不计收入或费用。相同币种不允许不等额充值，赠送额度须使用独立储值币种。各充值账户独立维护余额和平均成本，即使币种相同也不合并成本池。明确手续费独立计入费用，不加入本金。首页充值本金显示灰色，手续费独立显示红色，但仍属于同一笔交易。搜索按 `type` 筛选充值，编辑根据新的到账账户重新确定交易类型，不自动填充备注。外币之间换汇和同币种转账带走来源账户的成本，并加入目标账户的成本池；换回成本币种时，净资产变化为实际到账减去原成本。

消费使用原“支出”页面，金额输入付款账户原币数量，仍选择熟悉的费用分类。系统创建或复用该分类的同币种费用账户，父子分类按相同币种创建独立层级；镜像账户通过 `presetKey: currency-expense:<源分类账户ID>` 关联模板，不向原本币账户重复记账。消费只保存普通 `expense` 的两条分录，不使用换汇平衡账户。例如消费 22 储值单位、估算成本 20 元：资产分录 `{ amount: -200000, currency: { base: "CNY", target: "credit-id", amount: -220000 } }`，费用分录取正数。原币账户余额按 ±22 变化；本币统计与列表以“≈”预览 ±20，外部 amount 不参与复式平衡。

完整历史按 `time → createdAt → id` 重放。消费成本 = 消费数量 × 消费前剩余成本 ÷ 剩余数量；用 BigInt 中间计算并舍入至 0.0001，耗尽时取走全部剩余成本。新充值后将剩余成本与新本金、剩余数量与新到账数量分别相加，得到移动平均比例。编辑、补录、删除会重新估算后续消费，但原币 currency.amount 不变。本币估算不是账务真值：导入不因估算与最新成本不一致而拒绝有效原币分录；正常保存时重算预览。原币透支或不平衡仍拒绝原子保存。

“汇率与货币”统一显示剩余成本平均比例，余额耗尽后比例不再存在，下次换汇转入重新建立。同币种的不同账户独立核算成本；页面币种报价是这些余额和成本的加权比例，不能代替某个账户的实际成本。没有成本依据的外币收入或期初余额保留原币并标记成本未知；可记录有效原币消费，不生成本币估算或猜测 1:1。

## 购买交易的区间折旧与订阅摊销

原“复式”输入页以交易类型选择业务表单，依次提供转账、还款、购入资产、换汇／充值、借款到账、手动折旧，最后是自由分录。常用同币种业务只在顶部输入一次金额，自动生成等额借贷分录；第一账户决定币种，第二账户按业务角色及同币种过滤。还款为资产减少、负债减少；借款为负债增加、资产增加；购买为付款资产减少（或负债增加）、购入资产增加；手动折旧为资产减少、费用增加，保存为 `type: expense` 并计入当日费用。换汇／充值继续输入原币支付与到账金额及可选手续费。自由分录允许五类账户、多条分录及独立金额，已有复杂交易直接进入自由编辑，保留全部分录。

每件物品通过购买交易识别，可以复用“贵重物品”“电脑”“手机”等资产账户，不要求一物一账户。新账本不生成账户折旧规则或累计折旧抵减账户。账户的 fixed_asset / subscription 子类型仅用于分组和展示，折旧不依赖子类型，也允许普通资产账户。

在原“复式 → 购入资产”输入页勾选“自动生成折旧／摊销子交易”，设置排他结束日期（可按购买日期加月份快捷设置）、预计残值。折旧费用账户默认检查是否存在，无则创建对应币种账户。购买瞬间借记资产、贷记付款资产或负债；保存时自动生成唯一的 type: depreciation 子交易，借记折旧费用、贷记购买的资产账户。订阅通常设置残值为零。

子交易的 time 是折旧开始时间，endTime 是排他结束时间，entries 保存整个区间的总折旧额，金额＝购买原价－预计残值。区间及金额就是线性规则，不额外保存 depreciationRules、generatedByRuleId、使用期限或预计残值副本。预计残值由父交易的购入金额减去子交易总额还原，UI 月份仅用于计算绝对结束日期。领域入口还支持晚于购买日的 startTime。

saveDepreciatingPurchase 一次保存购买及其完整 children，重复编辑保留子交易 UUID 和创建时间，更新日期、金额、费用账户和标签；自动折旧子交易不复制父交易备注。列表与详情不重复展示子交易中与父交易相同的备注，独立备注正常展示。取消自动折旧后保存，只移除该购买的折旧子交易，其他关联记录保留。每笔购买最多有一笔此类子交易，拒绝孤立子交易、错误资产账户、超过购买成本的折旧及重复子交易。

getPurchaseDepreciationState 按购买 ID 计算已折旧额和剩余价值。余额只扣除截至查询时间已消耗的部分，收支、日图、月报和折旧图采用同一套区间交集和整数累计差额分摊，完整期间各段严格加总为总折旧额。每日不会写入新交易。折旧分析按购买交易计算使用中／折旧完状态；共用账户的多件物品在账户结构图中聚合，明细仍保留各自购买来源。不同币种优先使用每笔购买的成本依据换算，避免共用账户的购买成本混淆。

自动折旧／摊销（`type: depreciation`）按当地自然日分摊，购入当天在实际购入时刻确认当天的一份费用，随后每天零点确认下一份；结束边界排他，不再按分钟或毫秒不断增加当日费用。普通手动区间交易仍按实际时长分摊。首页、统计及资产余额采用同一截止读取，列表的区间条目显示截至今日累计金额，详情明确标记整个区间总额。主页购入资产条目以灰色单箭头显示付款账户的减少金额（外币按历史成本优先换算主货币），不将该金额计为支出；子交易统一展示在父条目备注区域，可分别点击查看详情，不再作为独立主页条目重复展示。单笔折旧直接显示“↳ 累计折旧”，省略计数和重复账户流向；多笔子交易默认收起为“关联记录（数量）”，展开后显示各业务名称和独立备注。嵌套子交易依次缩进；父条目缺失时仍独立展示子交易。列表金额按分四舍五入显示，两位小数不影响四位精度的存储、累计和图表；日期分组下右侧仅显示时分。主页隐藏摊销起止日期，具体区间在详情查看；搜索列表继续展开每笔交易并保留区间，跨年时显示年份。数据库金额仍为四位小数整数。

编辑子交易会打开来源父交易，在原购买页面直接修改期间及残值。账户管理只管理账户层级、类型、币种等，不提供账户折旧规则或每件物品的处置入口。新模型尚未实现按物品处置的自动损益及维修资本化版本，普通维修可以单独作为关联购买的支出交易，不自动修改折旧。

早期账户折旧规则、储值辅助面值与专用订阅领域实现已移除，业务仅使用购买区间子交易和统一币种成本池。开发阶段旧库和旧开发备份不自动迁移。

## 完整父子交易树

`Transaction.children?: Transaction[]` 保存完整直接子交易，允许递归层级。IndexedDB 与版本 17 的备份只保存根交易，子交易不会作为另一条根记录重复保存。折旧／订阅摊销使用 `type: depreciation`，通过购买交易的 `parentTransactionId` 关联并嵌入购买根记录。期间及总额本身表达线性规则，不保存账户规则。

领域和 store 的 `transactions` 保留包含所有交易的扁平计算视图。`flattenTransactionTree` 展开存储树并拒绝重复 ID、错误父引用、过深层级；`synchronizeTransactionChildren` 从该视图重建每个父级，校验缺失父交易和循环。读取、搜索、成本重放及统计只遍历扁平集合，不再递归累加 children，每笔分录只计算一次。

新增、更新、移除或移动子交易后，统一保存入口重建完整父级；数据库比较已存内容，为发生子树变化的父级更新 __update_at，并以父记录生成增量，和账户元数据、revision 原子提交。调用方不要同时把存储树和展开后的子交易当作根记录导入。

原输入页移除手动“关联父交易”。`getTransactionEditTarget` 将子交易及多层子交易编辑指向根父交易；父交易编辑页直接显示折旧期间、残值和已有子交易，保存时更新，取消自动折旧后保存时清除。普通支出、收入没有这些额外控件。开发阶段旧复式库和此前开发版本的文件不兼容或迁移，不提供旧 Cent 转换入口。

## 账本时区与 UTC 时间

`AccountingData.timeZone` 使用 IANA 时区名称，例如 `Asia/Shanghai`、`America/New_York` 或 `UTC`，保存到每个账本的 `__meta`，在原设置页选择。新账本默认使用设备时区。交易 `time`、创建／更新时间、期初交易及区间交易的起止时间仍保存 UTC Unix 毫秒时间戳，不保存附加时差，不把当地时间当作 UTC。

日期输入按账本时区解析成 UTC，列表、详情、搜索日期范围、统计分桶和购买交易的折旧分摊统一调用 `src/utils/time.ts`，日期显示与时区转换共用一个工具文件。工具只依赖 Day.js；应用启动时通过 `configureTime` 提供当前账本时区、语言和翻译的读取函数，界面使用 `bookDayjs` 或 `useBookTimeZone`，领域计算显式传入账本时区。切换时区不会改写原时间戳；同一 UTC 时刻可能归入不同的当地日期。按日折旧按日历天分摊，夏令时切换日允许 23 或 25 小时。不存在的当地输入时间拒绝保存，重复的当地时间取较早的 UTC 时刻。

新备份导出 `schemaVersion: 17` 并携带时区，导入验证时区有效性。仅读取当前格式；未设置时区时使用设备时区，保持原 UTC 时间戳。IndexedDB 库名及物理版本保持现有结构。

## GitHub 复式增量同步

原账本管理页面提供上传、立即同步和打开远端账本，复用原 GitHub 登录及 Blob／Tree／Commit 传输层。2.0 仓库使用独立前缀 `cent2-booking-`，不读取旧 `cent-journal-*`；`meta.json` 使用 `format: cent-accounting-sync`、`schemaVersion: 1`、`amountScale: 10000` 和账本名称，`meta` 内保存账户、时区、货币、标签及分析视图。账户是分类的升级，包含资产、负债、收入、费用、权益五种类型；所有交易仍使用原 `ledger` 文件组织，操作日志使用 `update/delete`，按 `ledger-<offset>.json` 分块。完整根交易包含 children，子交易不单独上传。同步版本与 JSON 备份版本是不同的协议。

`database/stash.ts` 统一提供快照三方合并、增量生成和日志重放。`__config.sync` 保存远端 ID、最后确认的基线和本地同步代次。合并基线、本地及远端：账户、根交易和子交易数组按 ID 合并，独立字段修改保留双方内容，删除与修改同一对象或不同修改同一字段时报错。分录及非 ID 数组作为整体处理；不能把不同版本分录拼接成不平衡交易。可选 undefined 字段按 JSON 缺省语义比较，避免误判删除冲突。合并结果通过完整领域校验后才上传或保存。

GitHub 上传携带读取时的 commit SHA；远端变更时重新拉取并重试合并，最多三次，更新 ref 禁止 force。上传成功后在同一 IndexedDB 事务内保存合并结果、更新基线并重建未发送日志；上传期间的新本地写入再次合并，保留待同步状态。上传失败、冲突和无效远端数据不确认本地日志；初次上传失败保留仓库关联，重试不创建重复仓库。若服务端已经提交而响应丢失，重试比较远端快照，不重复追加相同变化。

会话内缓存远端文件 SHA，仅重新下载发生变化的 metadata/chunk；首次读取会重放完整远端日志。已关联账本保存后自动同步，重新打开、窗口聚焦或恢复联网时拉取；同步失败可在账本管理重试。纯本地账本无需 GitHub。WebDAV、Gitee、S3 的复式适配尚未提供，旧 Bill 事件和读写接口不会接收新账本内容。
